# 运行与故障排查

## 定位与等待

v2.2 起，仅匹配 `https://gem.bullshot.io/*`。脚本注入非 Mining 路径时使用 `location.replace` 返回 Mining；站内无刷新导航每秒检查一次。这一行为不依赖挖矿开启状态。需要使用其他站内功能时，在 Tampermonkey 中禁用脚本。

脚本按目标矿场的 `h2` 标题限定其 Deploy；弹窗限定为 `role="dialog"` 且标题为 `Deploy to 目标矿场`，避免同名按钮串用。优先 Crystal Cavern，条件不足时回退 Greenstone Quarry。成功后每轮仍重新检查 Crystal，升级矿力后无需改脚本。

页面刷新或首次开始后，脚本等待页面初始化，尝试目标矿场跳转按钮，逐步滚动触发加载。找到标题后滚到按钮并再次确认。每个目标最多查找 60 秒，失败后才进入刷新恢复。

能量或矿力不足是正常条件不足，可触发回退；无法识别弹窗或目标不唯一属于异常，会刷新恢复，不会任意点击其他矿场。两个矿场都不能部署时按 Greenstone 缺能量的数字等待；其他条件不足使用手动设置的默认等待时间。

部署弹窗最多等待 15 秒，点击 Deploy miner 后最多等待 30 秒弹窗关闭。关闭仅是当前的页面完成信号，不是链上或服务器交易证明。

领取时每次只点击一个按钮；等待可领取按钮数量减少，最多 30 秒，再停顿 2.5～5.5 秒。按钮暂时禁用不单独视作完成。持续错误将自动刷新；不会要求用户反复手动点击开始。

## 时间语义

- 部署成功：停顿 4～6 秒后再试，能量充足时会连续部署。
- 缺少 N 点能量：按用户约定等待 N 分钟。该换算是假设，不是网站承诺。
- 手动更新等待时间：从现在重新计时，范围 0.1～1440 分钟。
- 自动刷新：保存开启状态后重新加载；成功注入脚本后立即尝试。旧倒计时不跨刷新保存。
- 所有延迟均受浏览器调度影响，不保证精确到秒。

## 常见问题

| 现象 | 检查与处理 |
| --- | --- |
| 没有面板 | 确认扩展和脚本启用、允许用户脚本，并直接刷新 Mining 页面 |
| 找不到 Greenstone Quarry | 等待滚动查找完成；确认已登录、网页加载正常，文案仍为英文且未改名 |
| 不领取奖励 | 当前可能正在部署、等待页面响应或存在其他弹窗；关闭无关弹窗后观察 |
| 领取后反复刷新 | 可能是服务器延迟超过 30 秒，或按钮数量没有减少；查看网站状态和控制台日志 |
| 能量不足却没有刷新 | 正常行为，按缺少点数换算分钟等待，避免无意义刷新 |
| 页面持续刷新 | 点击停止或禁用脚本，检查网络、登录和网站 DOM；重复刷新有 10～60 秒退避，但不会自动永久停止 |
| 刷新后又立即部署 | 开启状态被记住；刷新不会保留旧倒计时，会重新检查能量 |
| 后台运行变慢 | 避免电脑休眠、标签页冻结；浏览器后台节流仍可能发生 |

## 调试信息

打开 F12 → Console，过滤 `[Auto Deploy]`、`[Auto Collect]`、`[Auto Deploy Navigation]`。报告问题时建议提供脚本版本、面板提示、复现步骤、按钮 outerHTML 和去除敏感信息的截图。

不要提交 Cookie、令牌、助记词、私钥或完整浏览器存储。默认仓库不包含真实账户截图。

## 本地存储

| 键 | 位置 | 用途 |
| --- | --- | --- |
| bull-gems-auto-deploy-enabled-v1 | localStorage | 开始/停止状态 |
| bull-gems-wait-minutes | localStorage | 手动默认等待分钟数 |
| bull-gems-recovery | sessionStorage | 本标签页的刷新退避计数 |

没有多标签页互斥锁。必须只启用一个页面。随机停顿仅用于分隔操作，不代表模拟真实用户可信事件，也不保证绕过平台检测。
